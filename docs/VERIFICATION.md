# 확인 절차

현재 모든 인게임 단계는 미확인이다. 빌드/오프라인 검사는 런타임 검증을 대신하지 않는다.

## 완료한 정적 확인

- Windows/.NET10.0.402/KR Dalamud15.0.3.9 참조로 Debug 빌드: 경고0, 오류0.
- 로컬 게임 버전2026.10.06.0000.0000의 LogMessage 매크로와 SpecialShop 비용 관계 검사.
- SpecialShop 가격26,090건 중26,087건의 참조 아이템/이름 해석. Item8223을 참조하는3건은 이름이 없어 미확인.
- 특수 화폐28개 관계 중Item21173은 이름이 비어 런타임 매핑에서 제외. 현재 검사 대상 가격에는 해당 미확인 매핑 사용 없음.
- 자동 테스트/게임 프로세스 조작/플러그인 로드/공개 배포는 수행하지 않음.

## 대표 확인

1. Dalamud 개발 플러그인에 `src/DuckbillTweak.Plugin/bin/Debug/DuckbillTweak.dll`을 등록한다. 같은 폴더의 Core DLL도 필요하다. `/dbtw`가 열리는지 확인한다.
2. 상인 기능만 켠다. 길 상인 NPC 선택 후 `/dbtw shop`을 열어 게임 상점의 품목/기본 단가와 비교한다. 장비함/착용품/가방에 있는 품목과 등록한 수집품이 '보유/등록'으로 표시되는지 확인한다.
3. 전체 보기, 종류 선택, 종류별 있는 것 제외, 거래 가능/불가 필터를 바꾼다. 종류를 전부 해제하면0건이어야 한다. 미확인 품목이 숨겨지지 않아야 한다.
4. 석판·제작/채집 화폐·두 빛깔 보석 상점을 각각 확인한다. 재화 이름·가격·보유/부족량을 게임과 비교한다. 다른 교환 경로 선택 시 같은 품목이 두 번 계산되지 않아야 한다. 조건 확인이 필요한 품목은 기본 계산에서 제외돼야 한다.
5. PvP 말풍선 기능을 켜고 PvP 전장에서 같은 팀의 주변 플레이어가 보내는 파티/연합/일반 채팅을 확인한다. 발언자 위에 잠시 표시되고 이동을 따라가야 한다. 해제·지역 이동 후 이전 말풍선이 남지 않아야 한다. 주변에 없는 발언자는 표시하지 않아야 한다.
6. 8인 콘텐츠에서 입찰 기능을 켜고 새 전리품을 확인한다. 전리품 추가, 선택 완료, 숫자 수신, 획득 이름을 게임 채팅과 비교한다. 숫자를 받기 전에는 '미수신'이어야 하며 임의 숫자/포기를 표시하지 않아야 한다.
7. 24인 연합 콘텐츠에서3열 배치를 확인한다. 내 파티와 수신한 다른/미확인 소속을 구분해야 한다. 실제로 전원 숫자를 받는지, 언제 받는지와 입찰 권한의 범위를 별도로 기록한다.
8. 동일 아이템 동시 드롭은 구분 불가 안내가 나와야 한다. 월드가 다른 동명의 플레이어를 합치지 않아야 한다.
9. 기능을 각각 끄고 재로드/로그아웃/다른 캐릭터 접속을 확인한다. 예전 보유량·말풍선·입찰 기록이나 중복 명령/이벤트가 남지 않아야 한다.

확인할 때 사용 DLL 경로·게임/참조 버전·NPC 이름 또는 상점 ID·실제값/표시값 차이를 남긴다. 원본 게임 화면에 체크박스를 삽입하는 동작은 현재 개발본의 확인 대상이 아니다.
