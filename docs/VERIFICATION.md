# 확인 절차

현재 개발본은0.1.1.2이다. 상점과 입찰의 실기 실패 및 후속 수정을 아래에 기록했다. 이전판의 로드 확인을 화면/입력 검증으로 적용하지 않는다.

## 인게임 대표 확인 대기

1. 같은 정규 개발 DLL을 리로드하고 `/dbtw`를 연다. 게임 테마의 설정 화면과 세 개의 기능 체크박스가 보여야 한다. PvP에는 세부 채널/너비/시간 설정이 없어야 한다.
2. 상인 기능을 켜고 스크린샷의 일반 길 상점을 닫았다 연다. 원래 화면 안에 없는 것만 보기/종류 선택/필요 재화가 표시되고 별도 보조 목록은 없어야 한다.
3. 실제로 소지한 장비와 등록한 수집품이 제외되는지, 종류 선택별 제외 체크가 기억되는지 확인한다. 보유 미확인 품목은 숨겨지면 안 된다.
4. 필터 목록에서 알려진 품목 한 개를 좌클릭해 구매 확인 화면의 아이템/가격이 같은지 확인한다. 실제 구매는 직접 판단한다. 필터 해제, 매입 목록 탭 전환, 상점 재열기, 플러그인 해제 후 원래 위치/클릭/스크롤이 복구돼야 한다.
5. InclusionShop 카테고리/하위 카테고리 전환과 ShopExchangeItem에서 원본 인덱스/아이템/비용 연결을 확인한다. 연결 미확인 시 체크가 비활성화되고 원래 목록을 유지해야 한다. 잘못된 아이템을 선택하는 상태는 허용하지 않는다.
6. 상점의 필요 재화 버튼으로만 계산 화면을 연다. 기본 미보유, 종류/거래 여부/전체 보기를 확인하고 길·시학·제작/채집 화폐·두 빛깔 보석의 이름/필요/보유/부족량을 대조한다. 조건 미확인 제외와 부분 합계는 안내가 있어야 한다.
7. PvP에서 기본 말풍선을 켠 상태/끈 상태, 기본 채널 설정 변경, 전투 중/대기 중을 확인한다. 플러그인은 on/off만 제공하고 기본 설정을 따라야 한다. PvP 이탈·플러그인 해제 후 원래 동작으로 돌아와야 한다.
8. 8인 입찰 목록의 실제 아이템 행을 우클릭한다. 해당 아이템 이름이 위에, 이름/숫자가 한 열로 표시돼야 한다. 아이템을 바꾸면 제목/숫자도 바뀌어야 한다. 자동 팝업이나 비우기 버튼은 없어야 한다. 기본 컨텍스트 메뉴와 겹치는지 확인한다.
9. 24인은 세 열×8행을 확인한다. 실제 숫자를 받는 시점/입찰 권한의 범위를 기록한다. 미수신은 —이며 포기나0으로 추정하지 않는다. 같은 아이템 동시 드롭은 구분 불가 안내, 동명 다른 월드는 구분해야 한다.
10. 밝은/어두운 테마와 게임 UI 배율, 캐릭터/지역 전환, 플러그인 리로드/언로드에서 크기·글꼴·클릭 범위·중복 이벤트·잔여 노드를 확인한다.

## 0.1.1.0 상점 필터 실패와 0.1.1.1 수정

- 사용자 보고: 제외 체크가 작동하지 않고 체크 후 상점 스크롤까지 불능.
- 2026-10-26 17:14:55 부근 ShopExchangeItem 로그에서 `STX and ETX cannot be contained in the string` 예외가 ExchangeRowNode.SetNodeData/PopulateNodes/Update에 반복됨을 확인했다.
- 원인: 네이티브 ItemName.ToString에는 SeString 제어 문자가 남는데, 이를 일반 문자열로 게임 텍스트 노드에 전달했다. 렌더 예외가 원본 입력 복구 이전에 반복됐다.
- 수정: 상점과 입찰 진입점 모두 Item 시트 ExtractText 기반 이름을 사용한다. 숨은 대체 목록은 매 프레임 갱신하지 않는다. 모든 행의 표시 준비가 끝난 뒤 원본 입력 상태를 캡처/차단하며 예외와 체크 해제에서는 원본 입력을 먼저 복구한다. 같은 화면에서 렌더 실패를 반복하지 않고 다시 열 때 재시도한다.
- 카탈로그 연결 여부와 별도로 원본 보유 수/등록 API를 사용한다. 새 로그는 품목명 없이 Rows/Visible 수만 상태가 바뀔 때 기록한다.
- 정규 Debug/리소스 검사 통과,17:23:01.904 로컬 로그에서 수정본 로드 완료 확인. 상점 재열기 후 보유 품목 한 개 이상이 제외되는지, 휠/스크롤바와 해제 복구가 되는지 재확인해야 한다. 자동 테스트는 추가/실행하지 않았다.

확인 시 DLL 경로/게임·참조 버전/NPC 또는 상점 ID/실제값과 표시값 차이를 남긴다. 빌드/정적 검사를 대표 실기로 표시하지 않는다.

## 0.1.1.1 입찰 우클릭 실패와 0.1.1.2 수정

- 사용자 보고: 입찰 기능이 켜져 있어도 실제 아이템을 우클릭하면 아무 화면도 열리지 않음. 기존 코드에는 클릭 수신 진단이 없어 실제 이벤트가 어느 단계까지 왔는지는 확인하지 못했다.
- 기존 OwnerNode MouseUp/hovered item 의존을 제거했다. 실제 EventNode/충돌 노드 MouseDown과 목록 PreReceiveEvent의 우클릭 행을 대조한다. 복사한 행 ID는 다음 update에서 재검증하며 기본 입찰/포기 입력은 건드리지 않는다.
- 별도/정규 Debug 빌드 및 리소스 검사 통과. 17:33:40.321 수정본 로드 완료, 숫자 로그 지원true/7종 확인. 17:33:42.074 목록1행/클릭 노드1개 연결,17:33:43.570 실제 아이템3033 우클릭 수신/43.597 화면 요청 확인. 이후 사용자가 실제 숫자 창이 열린다고 확인했다. 실제 숫자 수신은 아직 확인하지 못했다. 자동 테스트는 추가/실행하지 않았다.
- 재활성화 후 `Loot log contract`로 숫자 형식 지원, 입찰 목록을 열어 `Loot click binding`의 Items/Rows/HitNodes를 확인한다. 실제 행 우클릭에서 `Loot right-click received`와 `Loot roll popup requested`를 구분한다. 마지막 메시지는 Open 호출 요청이며 실제 화면 표시를 보증하지 않는다.
- 실제 게임 로그 수신은 세션별 첫 `Loot log received`, 숫자 저장 성공은 `Loot roll recording active`로 구분한다. `Loot log could not be attributed`는 원문/이름/숫자 없이 실패 사유만 세션별 한 번씩 기록한다. 이미 지나간 숫자는 복원하지 않는다.
- 우클릭 화면 표시 외에8인/24인 배치와 실제 숫자, 제목 변경, 기본 컨텍스트 메뉴와의 관계, 중복 팝업/이벤트, 리로드/언로드 복구는 인게임 확인 대기다.
